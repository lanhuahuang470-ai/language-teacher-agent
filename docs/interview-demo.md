# 面试演示路线

## 建议的五分钟演示

1. 用新学生 ID 完成定级，展示结构化状态如何确定后续路径。
2. 点击提示，再回答题目，说明提示不写分数、不替换原题。
3. 同知识点连续答对两题，展示课程推进；答错展示正确答案与反馈分开保存。
4. 展示 assessments 唯一键和失败/重试测试：checkpoint 与业务幂等职责不同。
5. 展示个人错题过滤、持久化向量和运行日志；解释为何小规模使用 SQL 过滤与 Python 排序。
6. 展示评测基线与待验证项，说明将如何证明多 Agent 相对固定流程的收益。

实际录屏前应在独立演示数据库运行并检查，避免展示个人学习记录或密钥。

## 可以据实介绍的工程能力

- LangGraph 状态编排与显式事件路由。
- 按角色配置工具；运行时身份注入；个人数据检索隔离。
- Pydantic 输出验证、有限修复、非法评分不写库。
- 数据库事务、答题幂等、索引异步重试、向量持久化。
- Python 包组织、自动化回归、依赖版本记录和结构化日志。

## 简历描述草稿

基于 LangGraph 开发英语个性化教学助手，拆分规划、教学与评估职责；
实现结构化事件路由、个人错题检索隔离及基于题号的评分幂等，
通过事务与后台索引重试处理数据库/embedding 部分失败。
建立 58 项离线回归与可复现的判分评测入口。

这些数字需要真实实验后补充。

## 应能解释的问题

- 哪些决策交给 LLM，哪些必须由代码保证？
- 为什么 checkpointer 不自动保证业务写入恰好一次？
- 为什么“相似句子”不一定“相同语法错误”？
- 多 Agent 相比固定流程多出了哪些调用，收益如何测量？
- SQL 行锁、答题唯一键和浏览器题号分别解决什么问题？
- 当数据规模或应用副本数增加时，现有方案先在哪里遇到限制？
